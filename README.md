# msi-monitor-ctrl – Fedora Linux

A small Rust utility for switching the video input and KVM source on supported MSI monitors over USB, without MSI Gaming Intelligence.

This configuration was tested with:

```text
Monitor: MSI MPG 346CQRF X24
USB VID:PID: 1462:3fa4
```

Original project: <https://github.com/kdar/msi-monitor-ctrl>

## Changes compared with the original project

- Linux kernel-driver detachment before claiming the USB interface;
- avoids resetting an already active USB configuration on Linux;
- avoids calling `claim_interface()` twice for the same interface containing the IN and OUT endpoints;
- USB-C hotkey example;
- user-level systemd service;
- Fedora build and configuration instructions.

## 1. Fedora packages

Install Rust, the compiler, `pkg-config`, libusb, and GTK3 development dependencies:

```bash
sudo dnf install \
  git gcc gcc-c++ make rust cargo pkgconf-pkg-config \
  libusb1-devel gtk3-devel glib2-devel cairo-devel \
  pango-devel gdk-pixbuf2-devel atk-devel \
  libxcb-devel libX11-devel libXrandr-devel libXi-devel \
  libXtst-devel libxkbcommon-devel wayland-devel
```

`gtk3-devel` is required by the GTK backend used by `rfd` on Linux. The development packages provide `pkg-config` metadata such as `glib-2.0.pc`, `cairo.pc`, `gdk-3.0.pc`, and `pango.pc`.

Verify the basic dependencies:

```bash
rustc --version
cargo --version
pkg-config --modversion glib-2.0
pkg-config --modversion cairo
pkg-config --modversion gdk-3.0
```

## 2. Clone and compile

```bash
git clone https://github.com/krzysiek2788/msi-monitor-ctrl.git
cd msi-monitor-ctrl
cargo build --release --locked
```

The compiled binary will be located at:

```text
target/release/msi-monitor-ctrl
```

The `target/` directory is generated by Cargo and should not be committed to GitHub.

Run the program manually with:

```bash
./target/release/msi-monitor-ctrl --cmd ./usb-c.lua
```

## 3. USB access without root

Check that the monitor is detected:

```bash
lsusb -d 1462:3fa4
```

Install the included udev rule:

```bash
sudo cp 70-msi-monitor-ctrl.rules /etc/udev/rules.d/70-msi-monitor-ctrl.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

The rule contains:

```udev
SUBSYSTEM=="usb", ATTR{idVendor}=="1462", ATTR{idProduct}=="3fa4", TAG+="uaccess"
```

Disconnect and reconnect the monitor's USB cable after reloading the rules. Do not run the program as root.

## 4. Changing the keyboard shortcut

The shortcut is configured in:

```text
usb-c.lua
```

The current shortcut is:

```text
Ctrl + Alt + Shift + Right Arrow
```

It is defined by this line:

```lua
"shift+control+alt+ArrowRight",
```

For example, to use `Ctrl + Alt + Shift + F12`:

```lua
"shift+control+alt+F12",
```

Restart the service after editing the Lua file:

```bash
systemctl --user restart msi-monitor-ctrl.service
```

Do not run a manually started copy and the systemd service at the same time. Two copies will produce:

```text
HotKey already registered
```

## 5. Switching USB-C and USB-B upstream KVM

The active configuration is in `usb-c.lua`:

```lua
local callback = function()
  local dev = device_open(0x1462, 0x3fa4)
  dev:set_input(3)
  dev:set_kvm(2)
end
```

For the tested MPG 346CQRF X24 configuration:

```lua
dev:set_input(3) -- video input: Type-C
dev:set_kvm(2)   -- KVM source: Type-C
```

To use the USB-B upstream connection for the monitor's USB-A downstream ports, use:

```lua
dev:set_input(3)
dev:set_kvm(1)
```

USB-A ports on the monitor are downstream ports. The KVM upstream source is USB-B or USB-C.

If the video signal should come from DisplayPort or HDMI, change `set_input()` as well. The numeric values depend on the monitor model and its USB protocol, so values from this section may not work on every MSI monitor.

Always set the video input before changing KVM:

```lua
dev:set_input(3)
dev:set_kvm(2)
```

Changing KVM first may interrupt USB communication with the monitor.

## 6. Reading the current monitor state

Create a file named `check.lua`:

```lua
local dev = device_open(0x1462, 0x3fa4)
print("Current input:", dev:get_input())
print("Current KVM:", dev:get_kvm())
```

Run it with:

```bash
./target/release/msi-monitor-ctrl --cmd ./check.lua
```

## 7. Start automatically with the system

The repository contains:

```text
msi-monitor-ctrl.service
```

Install it as a user service:

```bash
mkdir -p ~/.config/systemd/user
cp msi-monitor-ctrl.service ~/.config/systemd/user/
```

The service uses `%h`, which means the current user's home directory:

```ini
WorkingDirectory=%h/msi-monitor-ctrl
ExecStart=%h/msi-monitor-ctrl/target/release/msi-monitor-ctrl --cmd %h/msi-monitor-ctrl/usb-c.lua
```

If the repository is stored elsewhere, change both paths in `msi-monitor-ctrl.service`. For example:

```ini
WorkingDirectory=/home/user/apps/msi-monitor-ctrl
ExecStart=/home/user/apps/msi-monitor-ctrl/target/release/msi-monitor-ctrl --cmd /home/user/apps/msi-monitor-ctrl/usb-c.lua
```

Enable and start the service:

```bash
systemctl --user daemon-reload
systemctl --user enable --now msi-monitor-ctrl.service
```

Check the status and logs:

```bash
systemctl --user status msi-monitor-ctrl.service --no-pager
journalctl --user -u msi-monitor-ctrl.service -f
```

Restart after changing the Lua script or service file:

```bash
systemctl --user restart msi-monitor-ctrl.service
```

Disable automatic startup:

```bash
systemctl --user disable --now msi-monitor-ctrl.service
```

## 8. Wayland and X11

Check the current session type:

```bash
echo "$XDG_SESSION_TYPE"
```

Global shortcuts should work without additional configuration on X11. On Wayland, global shortcut support depends on the desktop environment. If the service is running but the shortcut does not respond, inspect the logs:

```bash
journalctl --user -u msi-monitor-ctrl.service -b --no-pager
```

If necessary, test the application in an Xorg/X11 session.

## 9. USB diagnostics

```bash
lsusb -d 1462:3fa4
lsusb -t
lsusb -v -d 1462:3fa4 | \
  grep -E 'bConfigurationValue|bInterfaceNumber|bInterfaceClass|iInterface'
```

`Permission denied` usually indicates a udev permissions problem. `Resource busy` indicates that a USB interface is owned by a kernel driver or has been claimed twice by the application.

Do not unload the global `usbhid` module as a first troubleshooting step; that can disconnect unrelated USB keyboards and mice.
